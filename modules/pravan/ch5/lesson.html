Static and interactive sites (site statique, site interactif)

↑ contents
In plain words

A static site is a set of fixed files (HTML for the content, CSS for the look) stored on a server. The server hands out the same files to everyone. JavaScript can make such a site interactive: once the files have arrived, a script in the browser reacts to your clicks and changes the page. All of that happens on your own computer, and nothing goes back to the server.

  • static site (site statique)a site whose pages are fixed files: everyone gets exactly the same page.
  • client side (côté client)on the user's machine, inside the browser. The browser is called the client because it is the one asking for things.
  • server side (côté serveur)on the machine that stores and sends the site.
  • interactivity (interactivité)the page reacts to the user (a click shows, hides or changes something) without asking the server.a click on Ajouter adds a row
  • DOM (DOM)Document Object Model: the browser's live, in-memory copy of the page. JavaScript changes the page by changing the DOM. The file on the server stays the same.
  • developer tools (outils de développement)the browser panel (F12) that shows the page's code, the files downloaded (Network tab) and the console.
Worked example
The example: the people app (from TP3)

One web page with: a table of people, each row with a number, a last name (Nom), a first name (Prénom), a points value and a tick box; a summary line under the table (number of rows, total points); a small form with three boxes (Nom, Prénom, Points); and three buttons: Ajouter (add the typed person), Supprimer (delete the ticked rows), Console Tableau (print the table in the browser console).

It starts with 3 people: nom1 prenom1 5 points, nom2 prenom2 10 points, nom3 prenom3 15 points.

  1. What the browser got. In the developer tools (outils de développement, the panel that opens with F12), the Network tab lists every file the browser downloaded: the HTML file, the CSS file and the JavaScript file script.js. Clicking script.js and opening its Preview tab shows its full code. Anyone can do this, on any site.
  2. What a click does. Clicking Ajouter runs a function in script.js that adds a new <tr> (table row) to the DOM and recomputes the summary. With the 3 starting people the summary reads 3 rows, total 30 points (5 + 10 + 15).
  3. What a refresh does. Pressing F5 asks the server for the page again. The server still has the original file with 3 people, so any added person is gone. Nothing was ever sent to the server.

For TP3 that was fine. The next section asks what happens when we want more than that.

Two risks of browser-only code (les deux risques)

↑ contents
In plain words

Everything the browser runs, the visitor can read: the server had to send it to them. So code that holds secrets (a database password) must never be in script.js. And everything the browser runs uses the visitor's machine, which may be weak. So heavy calculations do not belong there either. The fix for both: keep that code on the server.

  • business code (code métier)the code that does the real work of the application: talking to the database, calculations, rules. Here, the code that is sensitive or heavy.connect to BD_Persons and insert a row
  • database (base de données (BD))a program that stores data in tables and keeps it after the page is closed. Usually protected by a password.BD_Persons, table Persons
  • security risk (risque lié à la sécurité)secrets in browser code are readable by anyone, and can be used to damage the data.
  • performance risk (risque lié à la performance)heavy code in the browser can be slow or freeze on a small device.
  • CPU, RAM (processeur, mémoire vive)the processor that does the calculations and the working memory that holds data while a program runs.
Worked example
The example: the people app (from TP3)

One web page with: a table of people, each row with a number, a last name (Nom), a first name (Prénom), a points value and a tick box; a summary line under the table (number of rows, total points); a small form with three boxes (Nom, Prénom, Points); and three buttons: Ajouter (add the typed person), Supprimer (delete the ticked rows), Console Tableau (print the table in the browser console).

It starts with 3 people: nom1 prenom1 5 points, nom2 prenom2 10 points, nom3 prenom3 15 points.

Scenario 1: add a button Enregistrer (Save)

Clicking it should store the people in a database called BD_Persons, protected by a password, then reload them from it. Suppose we write that in script.js. This is an invented sketch, only to show the problem:

// script.js  (downloaded by every visitor)
const db = connect("BD_Persons", "admin", "S3cret!");   // password in plain text
db.insert("Persons", { nom: "nom4", prenom: "prenom4", points: 20 });
LineWhat it does
line 2opens the database: name, user, password. All three are now visible to anyone who opens the file with F12.
line 3writes a person into table Persons. A visitor who copies this line can write (or delete) anything they want.

Scenario 2: add a button Prévision (Forecast)

Clicking it should run a long calculation that predicts each person's chance of passing an exam from their points. In script.js, it would run on the visitor's own processor (CPU) and memory (RAM), which may be a cheap phone.

The answer

Both risks disappear if this business code runs on the server instead: the visitor never receives it, and it uses the server's CPU and RAM. Section 3 shows how.

Dynamic pages (pages dynamiques)

↑ contents
In plain words

On a dynamic site, the page is not a file sitting on the server. A program on the server writes it at the moment you ask for it, using information it only knows then: what is in the database, the time, your name, what you typed in a form. The browser still receives ordinary HTML, CSS and JavaScript. It cannot tell, and cannot see, the program that wrote it.

  • dynamic site (site dynamique)a site whose pages are built by a program on the server for each visit, so their content can change.the list of people read from BD_Persons
  • dynamically generated page (page générée dynamiquement)an HTML page written by server code at request time.
  • server-side language (langage côté serveur)the language of the program that builds the pages. The course names PHP, Java, .NET and Python; the next part uses Python with Flask (a small library for writing web servers).
  • server-side interactivity (interactivité côté serveur)the page reacts to the user because the server sent back a different page.
Worked example
The example: Save in the people app

The people app (a table of people with Nom, Prénom, Points, and an Enregistrer button) now stores its data in a database BD_Persons. Its table Persons holds 7 people: Nom-1 to Nom-7, Prénom-1 to Prénom-7, with points 15, 14, 9, 10, 12, 13, 15.

  1. Click. The user clicks Enregistrer.
  2. Send. The browser sends the typed data to the server (sections 5 and 8 show exactly how).
  3. Write. The server runs the business code: it connects to BD_Persons with its password and inserts the data.
  4. Read and build. The server reads table Persons back and writes an HTML page with one <tr> per person.
  5. Answer. It sends that page. In F12 the visitor sees only the finished table. Risk 1 (security) is solved. For Prévision, the heavy calculation runs on the server's CPU and RAM. Risk 2 (performance) is solved.

Step 4 as pseudo-code

rows ← read every row of table Persons
html ← "<table>" + header row
k ← 1
for each person p in rows:
    html ← html + "<tr><td>" + k + "</td><td>" + p.nom + "</td><td>" + p.prenom + "</td><td>" + p.points + "</td></tr>"
    k ← k + 1
html ← html + "</table>"
send html to the browser
LineWhat it does
line 1asks the database for all rows of Persons. Here that gives 7 rows.
line 2starts the text of the page: the opening <table> tag and the header row (N°, Nom, Prénom, Points, Select).
line 3k is the row number shown in the first column.
lines 4-6repeats once per person: glues the person's values between HTML tags to make one table row, then adds 1 to k. With 7 people, it runs 7 times and makes 7 rows.
line 7closes the table.
line 8the text is sent as the body of the answer. The browser displays it like any HTML file.

Run on the course's table, this makes 7 rows with 88 points in total (15 + 14 + 9 + 10 + 12 + 13 + 15). Add an eighth person to the database and the next visit gets 8 rows, with no change to any file: that is what dynamic means.

Programs, IP addresses and ports (adresse IP, port, client, serveur)

↑ contents
In plain words

A browser and a web server are just two programs on two computers. For one program to reach another across a network, it needs two numbers: the IP address, which finds the computer, and the port, which finds the program on that computer. Think of a block of flats: the street address gets you to the building, the flat number gets you to the right door.

  • IP address (adresse IP)the number that identifies a computer on a network.93.140.10.40
  • port (port)a number (0 to 65535) that a waiting program reserves on its computer, so that incoming requests can be handed to it. One port, one program.1025; 80 for a web server
  • to listen (être à l'écoute)to wait on a port for requests to arrive. Being started is not enough: the program must be listening.
  • server (logical) (serveur logique)the program that waits for requests and answers them.P1, Apache
  • server (physical) (serveur physique)the machine that runs that program.Machine 1
  • client (client)the program that sends requests.P2, the browser
  • socket (socket TCP/IP)the connection point a program opens on a port, used to send and receive data over the network.
Worked example
The example: P2 wants documents stored on another machine

Machine 1 (IP address 93.140.10.40) stores documents. Several programs run on it: P1, P12, P13, P14. Machine 2 (IP address 173.160.10.3) runs a program P2 that wants those documents. We start a program P1 on Machine 1 whose job is to hand them out. P1 listens on port 1025. (The course writes the other ports as "port2", "port3", "port14"; here they get made-up numbers 2000, 3000, 4000.)

  1. What P1 must do. Stay running all the time (it cannot know when P2 will ask), listen on its port, and answer each request.
  2. Is the IP address enough? No. 93.140.10.40 gets the request to Machine 1, but Machine 1 runs four programs and would not know which one it is for.
  3. Add the port. P2 uses 93.140.10.40:1025: the part before the colon picks the machine, the part after picks the program.
  4. Checked for real. A small program listening on port 1025 of this computer was sent doc1.pdf and answered P1 here, you asked for: doc1.pdf. The same request to port 1026, where nothing listens, failed with ConnectionRefusedError: a wrong port reaches nobody.
  5. Names. P1, which waits and answers, is the server. P2, which asks, is the client. In web development the server is the web server, usually on port 80 (or 8080), and the client is the browser.

The HTTP request (la requête HTTP)

↑ contents
In plain words

HTTP is the agreed set of rules for the conversation between a browser and a web server. Because both sides follow the same rules, the server knows what a request will look like and the browser knows what an answer will look like. A request is plain text: a few lines of header that say what is wanted and where, then an optional body that carries data. Like a letter: the envelope says who it is for, the sheet inside says what you have to say.

  • protocol (protocole)a convention: the agreed format and order of messages between two programs.
  • HTTP (HTTP)HyperText Transfer Protocol, the protocol of the web. Each exchange is one request and one response.
  • request (requête)the message the client sends to the server.
  • header (en-tête)the first lines of a message: the method and path, then lines of the form Name: value.Host: monSite1.com
  • body (corps)the part after the empty line: the data itself, if any.Nom=BOB&Prenom=JOE&Points=15
  • method (verb) (méthode (verbe) HTTP)the first word of a request: what the client wants done.GET, POST, PUT, DELETE
  • resource (ressource)anything the server can hand out: a file, a page, a record in a database./index.html
  • domain name (nom de domaine)the human-friendly name of a site, turned into an IP address before connecting.monSite1.com
Worked example
The example: two requests to monSite1.com

First the browser asks for the page index.html of the site monSite1.com. Then it sends a new person (Nom BOB, Prénom JOE, Points 15) to the same server.

The HTTP response (la réponse HTTP)

↑ contents
In plain words

The server answers with a message built exactly like the request: a header, an empty line, a body. The first line holds the most important thing, a three-digit status code that says how it went. 200 means "here it is", 404 means "nothing here". The body holds what was asked for: an HTML page, a picture, or data such as a JSON list.

  • response (réponse)the message the server sends back for one request.
  • status code (code de statut)a three-digit number on the first line of the response. The first digit gives the family: 2 success, 3 go elsewhere, 4 the client's mistake, 5 the server's failure.200, 404
  • Content-Type (type de contenu)a header line naming the format of the body, so the client knows how to read it.text/html, application/json
  • JSON (JSON)a text format for data borrowed from JavaScript: [ ] for lists, { } for objects, names in double quotes.{"nom": "nom-1", "points": 5}

Form fields (les types de champs)

↑ contents
In plain words

A form is the part of a page where the user types or picks values to send to the server. HTML has a different field for each kind of value: free text, a phone number, a date, one choice among several, a file. Picking the right field type helps the user (a date picker, a number with arrows) and lets the browser refuse wrong values before anything is sent.

  • form (formulaire)an HTML element that collects what the user enters and sends it to the server.
  • field (champ)one place to enter a value. Most are <input> with a type.<input type="email">
  • attribute (attribut)an extra setting written inside a tag as name="value".min="0"
  • name (attribut name)the key under which the field's value is sent. No name, not sent.name="nom" → nom=BOB
  • validation (validation (maîtriser la saisie))the browser checks the value against the field's rules (pattern, min, max, minlength, required) and refuses to send the form if one fails.
  • pattern (motif)a model the text must follow, written as a regular expression: [0-9] is one digit, {3} means three times.[0-9]{2} = two digits
Worked example
The example: the course's catalogue of fields

The course shows one example of each kind of field. Below is each one with its code, what it accepts, and what happened when test values were typed into it in a real browser (Chromium, asking the field checkValidity(): "is this value allowed?").

The form element: action and method (structure d'un formulaire)

↑ contents
In plain words

The <form> tag wraps the fields and says two things: where to send them (action) and how (method, GET or POST). When the user clicks Submit, the browser turns every field into name=value, glues the pairs together with &, and sends an HTTP request: with GET the pairs go in the address, with POST they go in the body.

  • action (attribut action)the address of the server program that receives the data.action="page_traitement"
  • method (attribut method)the HTTP method used to send: get or post.method="post"
  • query string (chaîne de requête)the part of an address after ?, holding GET data.?nom=BOB&prenom=JOE
  • submit (soumettre)to send the form: the browser builds and sends the request.
  • URL encoding (encodage URL)rewriting special characters as % + two hex digits so they cannot break the name=value&… format.@ → %40
Worked example
The example: sending a person to the server

A form with three text fields named nom, prenom and points (the people app's three boxes). The user types BOB, JOE and 15 and clicks Submit. On the server, a program at the address page_traitement will receive the data.

  <input type="number" id="points" name="points"/><br><br>

<form …> … </form>everything between the two tags belongs to the form. It goes inside <body>.
action="page_traitement"where to send the data: the address of the server program that will process it.
method="post"how to send it: the HTTP method. post puts the data in the request body. To send data to a server, a form uses only get or post.
<label for="nom">the visible text Nom:, tied to the field whose id is nom.
id="nom"a unique name for the element inside the page (used by the label and by JavaScript).

type="submit"the button that triggers the sending.

Install, start and deploy with Apache (installation d'un serveur Apache en local)

↑ contents
In plain words

To try a site the way visitors will see it, you need a web server. Apache is a free, widely used one, and it can run on your own PC. Your computer then plays both roles: Apache is the server, your browser is the client, and they reach each other through the special address localhost. Apache serves whatever is in one folder, htdocs; putting your project there is "deploying" it.

  • Apache (Apache)a free web server program. On Windows its program file is httpd.exe.
  • local server (serveur local)a server running on the same computer as the browser.
  • localhost (localhost)the name a computer uses for itself. It stands for the IP address 127.0.0.1.localhost:80
  • htdocs (répertoire htdocs)the folder Apache serves files from. The address localhost/x/y.html means the file htdocs\x\y.html.
  • deploy (déployer)to put a site in the place a server serves it from.copy monProjet into htdocs
  • Command Prompt (invite de commandes)the Windows window where you type commands instead of clicking.cmd
Worked example
The example: installing Apache on Windows and putting monProjet online on your PC

You have a small website in a folder monProjet (the pages from TP0, with an index.html). You want to see it through a real web server, Apache, running on your own computer.

  1. Download. From https://www.apachelounge.com/download/, take the zip file for Windows. A zip is a compressed archive: one file that holds a whole folder.
  2. Unzip and copy. Unzip it, find the folder Apache24 inside, and paste it at the root of drive C, so it becomes C:\Apache24.
  3. Start it. Open the Command Prompt (invite de commandes: Windows key, type cmd, Enter) and type the two commands below.
cd C:\Apache24\bin
httpd.exe
PartWhat it means
cdchange directory: moves the Command Prompt into a folder, so the next commands run from there.
C:\Apache24\binthe folder to move into: bin (short for binaries, the runnable programs) inside Apache24. The course writes C:\apache\bin, but the folder you copied is named Apache24.
httpd.exeruns the Apache program. httpd = HTTP daemon, a daemon being a program that runs in the background and waits. It now listens on port 80. Leave the window open: closing it stops the server.
  1. Test. In the browser, open localhost:80. The page says It works!. That page is the file C:\Apache24\htdocs\index.html. Change "It works!" to "Hello World" in that file, refresh, and the page changes: the server just sends whatever file is there.
  2. Deploy. To deploy (déployer, put a site where the server can serve it) copy the folder monProjet into htdocs, giving C:\Apache24\htdocs\monProjet.
  3. Open it. Go to localhost:80/monProjet. Nothing comes after monProjet/, so Apache looks for an index.html in that folder and sends it.
  • localhost is the name every computer gives itself; it means the address 127.0.0.1 (checked on this machine). A request to it never leaves your PC, so one computer plays both Machine 1 (server) and Machine 2 (client).
  • :80 can be left out: a browser uses port 80 when none is written. localhost and localhost:80 are the same page.
  • The rule "address → file in htdocs, index.html when the address ends with a folder" was checked with a small Python server that follows it: localhost/ gave htdocs/index.html and localhost/monProjet/ gave htdocs/monProjet/index.html. (Apache for Windows itself could not be run here.)

A virtual host (mise en place d'un virtual host)

↑ contents
In plain words

One Apache can serve several sites, each under its own domain name, even though they all share the same IP address and port. Each site is described by a virtual host: a name and a folder. When a request arrives, Apache reads its Host line and serves the folder of the matching virtual host. On your PC, you also tell Windows that the name means "this computer", using the hosts file.

  • virtual host (vHost) (hôte virtuel)one site, among several, served by the same Apache: a domain name tied to a folder.ferrariproject.dz → htdocs/monProjet
  • configuration file (fichier de configuration)a text file of settings that a program reads when it starts.httpd.conf
  • comment (commentaire)a line the program ignores; in Apache files it starts with #.
  • DNS (DNS)Domain Name System: the service that turns domain names into IP addresses.
  • hosts file (fichier hosts)a small file on your PC that maps names to IP addresses. It is read before DNS, so it can override it, for your PC only.127.0.0.1 FerrariProject.dz
  • restart (redémarrer)stop and start the server so it reads its settings again.Ctrl+C, then httpd.exe
Worked example
The example: serving monProjet as ferrariproject.dz

Apache is installed in C:\Apache24 and the site is in C:\Apache24\htdocs\monProjet (section 9). Instead of typing localhost/monProjet, we want to type the domain name the real site will have, ferrariproject.dz, to work in the same conditions as the final deployment.

1. Describe the site to Apache

At the bottom of C:\Apache24\conf\extra\httpd-vhosts.conf (a configuration file: a text file of settings Apache reads when it starts), add:

<VirtualHost *:80>
    ServerAdmin webmaster@ferrariProject.dz
    DocumentRoot "${SRVROOT}/htdocs/monProjet"
    ServerName ferrariproject.dz
    ServerAlias ferrariproject.dz
    <Directory "${SRVROOT}/htdocs/monProjet">
        Options Indexes FollowSymLinks
        AllowOverride All
        Require all granted
    </Directory>
</VirtualHost>
LineWhat it does
<VirtualHost *:80>starts one virtual host, for requests arriving on any of the PC's addresses (*) on port 80.
ServerAdminthe e-mail address shown on Apache's error pages.
DocumentRootthe folder this site is served from. ${SRVROOT} is a variable meaning Apache's own folder, here C:/Apache24.
ServerNamethe domain name this block answers to. Apache compares it with the request's Host line.
ServerAliasother names for the same site. Here it repeats the ServerName, so it adds nothing; it would be used for e.g. www.ferrariproject.dz.
<Directory …>rules for that folder.
Options Indexesif a folder has no index.html, show the list of its files.
FollowSymLinksallow shortcuts (symbolic links) inside the folder.
AllowOverride Allallow settings files (.htaccess) inside the folder to change these rules.
Require all grantedeveryone may see the folder.

2. Make Apache read that file

In C:\Apache24\conf\httpd.conf, find the line below and delete the # at its start. A # turns a line into a comment, which Apache ignores.

# Include conf/extra/httpd-vhosts.conf      ← before
Include conf/extra/httpd-vhosts.conf        ← after

3. Make the name point to your PC

Normally a name is turned into an IP address by DNS (Domain Name System, the internet's phone book). Before asking DNS, Windows reads the hosts file, C:\Windows\System32\drivers\etc\hosts. Add at its bottom (open the editor "as administrator", or Windows will not let you save):

127.0.0.1 FerrariProject.dz
PartWhat it means
127.0.0.1the IP address to use: your own PC (localhost).
FerrariProject.dzthe name. Capitals do not matter in domain names, so it also covers ferrariproject.dz.

4. Restart and test

Apache reads its settings only when it starts. In the Command Prompt where it runs, press Ctrl+C to stop it, then type httpd.exe again. Now open ferrariproject.dz in the browser: you get monProjet's index.html. Checked with a small Python server that picks the folder from the Host line the same way: Host FerrariProject.dz, path / gave htdocs/monProjet/index.html.

In production

On a real site, htdocs is on a distant physical server, and you copy monProjet into it with an FTP client such as FileZilla (FTP = File Transfer Protocol, a protocol for sending files to a server).

Notes on the original course
  • Slide 47: HTTP stands for HyperText Transfer Protocol, not "HyperText Transport Protocole".
  • Slides 53-56: Machine 1's address is written 93.140.10.40 on the machine but 93.141.10.40:1025 in the address P2 uses. They must be the same; this lesson uses 93.140.10.40.
  • Slides 38-39: the table Persons holds Nom-1, Prénom-1, but the generated HTML beside it shows Nom1, Prénom1. The generated rows should copy the database exactly.
  • Slides 69-73: the request line is written Get /index.html. Methods are written in capitals (GET), and the line ends with the HTTP version: GET /index.html HTTP/1.1.
  • Slides 69-72: the GET request carries Content-Type: application/x-www-form-urlencoded, but a GET has no body, so there is nothing to describe. A real browser's GET has no Content-Type line (checked in Chromium).
  • Slide 73: the POST body is drawn as three lines Nom = BOB …; on the wire it is one line, Nom=BOB&Prenom=JOE&Points=15, and the header also needs Content-Length: 28.
  • Slides 75-78: the response date Thu, 17Nov2021 has two errors: 17 November 2021 was a Wednesday, and the format needs spaces: Wed, 17 Nov 2021 09:30:05 GMT.
  • Slides 75-78: the JSON body is not valid JSON: names must be in double quotes ("nom", not nom). A JSON reader rejects it (Expecting property name enclosed in double quotes). The third person also reads prenom- instead of prenom-3.
  • Slide 78: status code 201 is Created, not "Accepted" (that is 202). It is most often the answer to a POST, not only a PUT.
  • Slide 95: the slide asks which method to put in method among GET/POST/PUT/DELETE. A form can only send get or post; any other value is treated as get (checked in Chromium: method="put" sent a GET).
  • Slides 92-95: <label for="nom"> points to an input that has name="nom" but no id. for matches the id, so the label is not tied to its field; add id="nom" (and id="prenom").
  • Slide 105: the command cd C:\apache\bin does not match the folder copied in slide 104, C:\Apache24; it should be cd C:\Apache24\bin (as slides 108 and 114 also use).
  • Slide 114: ServerAlias repeats the ServerName, so it does nothing; an alias is for a second name such as www.ferrariproject.dz.
  • Slide 119: "Filzilla" is FileZilla, and FTP is File Transfer Protocol.
